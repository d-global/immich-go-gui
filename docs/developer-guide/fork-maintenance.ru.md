# Правила сопровождения форка

[English](fork-maintenance.md) · **Русский**

Этот документ фиксирует, как `d-global/immich-go-gui` сопровождается как публичный fork проекта `shitan198u/immich-go-gui`.

## Основные принципы

1. **Сохранять историю upstream.** Не переписывать upstream-коммиты и не удалять исходное авторство или лицензионные уведомления.
2. **Держать `master` близко к upstream.** Fork-специфичная разработка идёт в feature-ветках и вливается только после успешных тестов.
3. **Повторно использовать upstream-компоненты.** Новые функции должны интегрироваться с существующими профилями, keyring, command builder, runner, логированием, темой, packaging и CI, а не дублировать их.
4. **Никаких секретов в Git.** API-ключи, приватные URL, локальные credentials, содержимое личных архивов и машинные секреты не коммитятся.
5. **Двуязычная документация форка.** Новая пользовательская документация fork-специфичных функций должна быть на английском и русском. Английский остаётся основным языком кода, идентификаторов, commit messages и PR в upstream.
6. **Небольшие проверяемые изменения.** Предпочитать небольшие focused commits и Draft PR вместо больших непрозрачных переписываний.

## Ветки

- `master` — стабильная база форка, периодически синхронизируемая с upstream `master`.
- `feature/*` — разработка новых функций форка.
- `fix/*` — точечные исправления.
- `docs/*` — документация, когда для неё нужна отдельная ветка.

Текущая ветка Archive Migration:

`feature/archive-migration-queue`

## Синхронизация с upstream

Fork периодически синхронизируется с:

`shitan198u/immich-go-gui:master`

Рекомендуемый порядок:

1. посмотреть изменения upstream и release notes;
2. обновить fork `master` из upstream;
3. прогнать оригинальные upstream-тесты без изменений;
4. обновить активные feature-ветки от свежего fork `master`;
5. разрешать конфликты в fork-коде, не меняя без необходимости чужую upstream-логику;
6. снова прогнать тесты на Linux/macOS/Windows там, где это поддерживает CI.

## Pull Request

Fork PR должны:

- быть направлены в `master`;
- начинаться как Draft, пока функция не готова;
- использовать Conventional Commit style в коммитах и заголовках;
- описывать fork-специфичные пользовательские изменения на английском и русском;
- содержать тесты для новой core-логики;
- обновлять парные English/Russian docs для пользовательских функций.

PR обратно в `shitan198u/immich-go-gui` должны следовать upstream CONTRIBUTING и быть в первую очередь на английском.

## Releases

Fork release публикуется только после того, как:

- feature PR влит в fork `master`;
- CI зелёный;
- Windows-сборка проверена на реальной машине;
- migration workflow проверен на безопасном тестовом архиве;
- подготовлены английские и русские release notes;
- сохранены upstream attribution и MIT License.

Release notes должны отдельно показывать:

- на какой upstream-версии основан релиз;
- что именно добавлено в fork;
- известные ограничения;
- совместимость с проверенными версиями `immich-go` и Immich.

## Языковая политика документации

Для fork-специфичной пользовательской документации:

- English: `name.md`
- Русский: `name.ru.md`
- в начале оба файла ссылаются друг на друга;
- функциональность, предупреждения и ограничения должны совпадать по смыслу;
- скриншоты можно использовать общие для нейтрального UI; после появления локализации интерфейса желательно поддерживать локализованные варианты.

Чисто технические внутренние заметки разработчиков могут оставаться на английском, но публичный feature design и release documentation должны иметь русскую пару.

## Безопасность и приватность

Никогда не коммитить:

- Immich API keys или admin keys;
- приватные server tokens;
- локальные имена файлов, если они без необходимости раскрывают личные данные;
- личные фотографии или экспортированные metadata;
- базы данных с пользовательским состоянием;
- логи с секретами или приватными путями, если они не очищены.

Для секретов использовать upstream keyring/env-механику, а не создавать отдельный механизм форка.

## Авторство и сопровождение

- Исходный проект и оригинальное авторство принадлежат `shitan198u/immich-go-gui` и его contributors.
- Fork-специфичные изменения и сопровождение ведутся под `d-global`.
- MIT License сохраняется без изменений.
