# Очередь миграции архива

[English](archive-migration.md) · **Русский**

Этот fork добавляет управляемый сценарий разовой миграции старых фотоархивов поверх уже существующих возможностей Immich-Go GUI. Он намеренно отделён от Backup Monitor.

## Цель

Перенести старый вручную организованный фотоархив так, чтобы каждая **папка первого уровня** становилась отдельным альбомом Immich, а для каждой папки сохранялось устойчивое состояние. Пользователь должен иметь возможность остановить работу, перезапустить программу и продолжить без гадания, что уже было загружено.

Пример:

```text
Корень архива/
├── Красная Поляна/
│   ├── 2018/
│   └── Видео/
├── Анапа/
└── файл-в-корне.jpg
```

Элементами очереди будут только `Красная Поляна` и `Анапа`. Все вложенные папки включаются в соответствующего родителя первого уровня. Файлы, лежащие прямо в корне архива, считаются отдельно и должны обрабатываться явно, а не незаметно смешиваться с каким-либо альбомом.

## Использовать upstream, а не переписывать его

Функция должна максимально использовать существующие компоненты upstream:

- профили и API-ключи из системного keyring;
- предварительную проверку соединения;
- управление бинарником `immich-go`;
- существующий registry флагов `upload-folder` и command builder;
- существующий background/hidden folder runner там, где он подходит;
- правила хранения логов и process-safety;
- тему, навигацию, виджеты и packaging.

Нельзя создавать второй storage API-ключей, второй downloader бинарника или альтернативный command builder.

## Постоянный жизненный цикл

Каждая папка первого уровня имеет одно из состояний:

- `TODO` — обнаружена, ещё не подготовлена;
- `READY` — выбрана/подготовлена к загрузке;
- `UPLOADING` — загрузка выполняется;
- `DONE` — immich-go завершился успешно, а целевой альбом Immich проверен через сервер и содержит ровно ожидаемое количество assets;
- `PARTIAL` — обработка дала прогресс, но серверная проверка альбома сошлась не полностью;
- `ERROR` — ошибка загрузки или серверной проверки альбома;
- `SKIP` — исключена намеренно.

Повторное сканирование обновляет количество файлов и размер, но сохраняет lifecycle для того же пути папки.

Состояние хранится отдельно для каждого профиля в `archive_migration_state.json` рядом с существующими файлами конфигурации профиля.

Archive Migration не считает exit code immich-go или счётчик `added to album` доказательством реального состава альбома. После каждого успешного запуска CLI программа отдельно обращается к Immich, находит один целевой альбом с точным совпадением имени и требует, чтобы его `assetCount` точно совпадал с количеством обработанных assets. Отсутствующий, неоднозначный, недоступный, пустой, неполный или переполненный альбом остаётся в `ERROR` или `PARTIAL`, а не превращается в ложный `DONE`.

В schema v2 добавлено это правило завершения. Любой `DONE`, записанный schema v1, при загрузке состояния переводится в `PARTIAL`, потому что старое состояние было создано до серверной проверки результата.

## Целевой UX

Будущая страница должна быть рабочей панелью, а не пошаговым wizard:

1. выбрать корень архива;
2. просканировать immediate child folders;
3. искать, сортировать и фильтровать таблицу;
4. при необходимости скрывать строки `DONE`;
5. выбирать несколько папок;
6. назначать общий тег и параметры очереди;
7. выполнять загрузку последовательно, по одной папке;
8. создавать для каждой выбранной папки первого уровня альбом Immich с тем же именем;
9. после успешного CLI-run проверять целевой альбом непосредственно через Immich API;
10. сохранять `DONE / ERROR / PARTIAL` после каждой папки, а не только в конце всей очереди.

Интерфейс должен показывать текущую папку, позицию в очереди, прогресс и связанный лог без необходимости искать их по другим вкладкам.

## Этапы реализации

### Phase A: состояние + scanner

- Qt-free модели и persistence;
- scanner immediate child folders;
- рекурсивный подсчёт количества файлов и размера;
- отдельный подсчёт файлов в корне;
- cancellation и progress callbacks;
- тесты сохранения lifecycle при повторном сканировании.

### Phase B: каркас страницы

- новая навигация/страница Archive Migration;
- выбор источника и команда сканирования;
- сортируемая и фильтруемая таблица;
- переключатель `Hide DONE`;
- summary выбранных элементов.

### Phase C: runner очереди

- один `upload-folder` plan на каждую выбранную папку;
- принудительное правило «одна папка первого уровня = один альбом»;
- общий тег по желанию;
- последовательное выполнение по умолчанию;
- политика stop/continue on error;
- сохранение состояния после каждой папки;
- live log и прогресс очереди.

### Phase D: импорт старого состояния

Опционально импортировать статусы из SQLite-базы замороженного проекта `d-global/immich-archive-manager`. Это только средство миграции. Новый fork не должен зависеть от runtime или формата хранения старой программы.

## Не входит в задачу

- Замена существующих вкладок Upload.
- Замена Backup Monitor.
- Удаление исходных файлов.
- Повторная реализация профилей, хранения API-ключей, binary manager или CLI parity.
